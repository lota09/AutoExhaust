# ESP8266 (Wemos D1 R1) 기술 분석 보고서

Bambu Lab X1C 연동 시스템을 ESP8266 환경으로 이식하며 적용된 주요 기술적 해결책과 그 원리를 정리합니다.

## 1. WiFi 연결 성공의 이유 (Enhanced WiFi)

기존 기본 예제 코드가 최신 공유기(TUF-AX5400) 환경에서 실패했던 원인과 해결책은 다음과 같습니다.

*   **Smart Connect 호환성**: 최신 라우터는 2.4GHz와 5GHz를 하나의 SSID로 묶어 기기에 따라 대역을 할당합니다. 2.4GHz 전용인 ESP8266은 이 과정에서 통신 오류를 일으키기 쉬운데, `WiFi.setPhyMode(WIFI_PHY_MODE_11G)`를 통해 802.11g 모드로 강제 고정함으로써 연결 안정성을 확보했습니다.
*   **절전 모드 비활성화 (`WIFI_NONE_SLEEP`)**: 기본 설정에서는 전력 절감을 위해 WiFi 라디오를 간헐적으로 끕니다. 이 짧은 찰나에 공유기와의 핸드셰이크 패킷을 놓치면 연결이 끊기거나 리셋(`rst cause:4`)이 발생합니다. 이를 비활성화하여 패킷 유실을 막았습니다.
*   **WDT(Watchdog Timer) 관리**: 연결이 지연될 때 하드웨어 워치독이 리셋을 걸기 전에 소프트웨어적으로 `ESP.restart()`를 호출하여 시스템이 무한 루프나 패닉에 빠지지 않도록 제어했습니다.

## 2. ArduinoJson Filter 기능 분석

뱀부랩 프린터가 송신하는 MQTT 메시지는 수 킬로바이트(KB)에 달하는 거대 JSON입니다. 이를 ESP8266의 작은 램(RAM)에 그대로 올리면 즉시 메모리 부족으로 시스템이 붕괴됩니다.

*   **작동 원리**: `DeserializationOption::Filter`를 사용하면 파서(Parser)가 데이터를 읽는 도중, 필터에 정의되지 않은 키(Key)와 값(Value)은 메모리에 담지 않고 즉시 버립니다.
*   **효과**: 
    *   **전체 데이터**: 5KB 이상의 큰 덩어리
    *   **필터링 후**: `gcode_state`, `temper` 등 핵심 정보만 남겨 약 200~500 바이트 수준으로 압축
*   **결론**: 이 기법 덕분에 램 용량이 넉넉하지 않은 ESP8266에서도 거대한 프린터 상태 보고서를 안정적으로 처리할 수 있게 되었습니다.

## 3. SSL(MQTTS) 최적화

뱀부랩의 MQTT는 보안 포트(8883)를 사용하므로 SSL/TLS 암호화 연산이 필요합니다. 이는 ESP8266에게 매우 무거운 작업입니다.

*   **`setInsecure()`**: 서버의 인증서 체인을 검증하는 과정을 생략합니다. 보안상으로는 신뢰할 수 있는 서버라는 가정이 필요하지만, 프린터 내장 브로커에 접속하는 로컬 환경에서는 연산 부하를 줄이는 가장 효과적인 방법입니다.
*   **`setBufferSizes(512, 512)`**: SSL 통신 시 데이터를 담아두는 버퍼 크기를 최소한으로 제한합니다. 기본 버퍼 사이즈(보통 16KB)는 ESP8266의 힙(Heap) 영역을 거의 다 차지해버리는데, 이를 줄임으로써 다른 로직(JSON 파싱 등)이 돌아갈 공간을 확보했습니다.

## 4. 종합 평가

ESP8266(Wemos D1 R1)은 구형 칩셋이지만, 위와 같은 **트래픽 필터링**과 **메모리 버퍼 최적화** 기법을 적용하면 최신 3D 프린터의 데이터 모니터링 및 제어 장치로서 충분히 제 성능을 발휘할 수 있습니다.
